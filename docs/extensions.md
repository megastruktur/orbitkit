# OrbitKit Extension Guide

OrbitKit enforces an architectural principle of **minimal core permissions**: the core `tauri-plugin-orbitkit` plugin declares only `SYSTEM_ALERT_WINDOW` on Android and requires zero elevated permissions on desktop platforms.

Domain-specific capabilities — such as background audio recording, system tray integration, or sensor telemetry — should be structured as modular Tauri plugins that extend OrbitKit.

This guide walks through writing an extension, using the bundled `tauri-plugin-orbitkit-recorder` crate as a concrete reference.

---

## 1. Extension Architecture Pattern

```
+--------------------------------------------------------------------------+
|                           Consumer Application                           |
+--------------------------------------------------------------------------+
                  |                                      |
                  v                                      v
    +---------------------------+          +---------------------------+
    |   tauri-plugin-orbitkit   |          | tauri-plugin-orbitkit-... |
    |   (Core Overlay Shell)    |          |   (Domain Extension)      |
    +---------------------------+          +---------------------------+
                  |                                      |
                  | SAW Only                             | Audio / FGS / Sensor
                  v                                      v
    +---------------------------+          +---------------------------+
    |   Android WindowManager   |          |  Android Foreground Svc   |
    +---------------------------+          +---------------------------+
```

An OrbitKit extension typically consists of:
1. **Rust Crate**: Implements `tauri::plugin::Builder` and exposes a typed extension trait (e.g. `OrbitkitRecorderExt`) on `AppHandle`.
2. **Platform Native Backends**:
   - `desktop.rs`: Implements desktop behavior (Linux/macOS/Windows).
   - `mobile.rs`: Binds to Android Kotlin via Tauri mobile plugin macros.
3. **Android Module (`android/`)**:
   - Isolated `AndroidManifest.xml` declaring only the permissions required by the extension.
   - Dedicated `Service` or background worker classes.
4. **Permissions Directory (`permissions/`)**:
   - Tauri v2 capability definitions (`default.toml`) and autogenerated command permissions.

## 2. Reference Implementation: `tauri-plugin-orbitkit-recorder`

The `tauri-plugin-orbitkit-recorder` plugin demonstrates an audio recording extension featuring background foreground service lifecycle and crash/LMK state persistence.

### Cargo Configuration (`Cargo.toml`)

```toml
[package]
name = "tauri-plugin-orbitkit-recorder"
version = "0.1.0"
edition = "2021"

[dependencies]
tauri = { version = "=2.11.6", default-features = false }
serde = { version = "1.0", features = ["derive"] }
serde_json = "1.0"
thiserror = "2.0"
log = "0.4"
```

### Isolated Android Permissions (`android/src/main/AndroidManifest.xml`)

Notice how sensitive permissions are kept strictly inside the extension module:

```xml
<manifest xmlns:android="http://schemas.android.com/apk/res/android">
    <uses-permission android:name="android.permission.RECORD_AUDIO" />
    <uses-permission android:name="android.permission.FOREGROUND_SERVICE" />
    <uses-permission android:name="android.permission.FOREGROUND_SERVICE_MICROPHONE" />
    <uses-permission android:name="android.permission.POST_NOTIFICATIONS" />

    <application>
        <service
            android:name="dev.orbitkit.native.OrbitkitRecorderService"
            android:exported="false"
            android:foregroundServiceType="microphone" />
    </application>
</manifest>
```

## 3. Extension Command Surface

The recorder extension registers eight Tauri commands under the plugin prefix `plugin:orbitkit-recorder|<cmd>`:

| Command | Arguments | Return Type | Description |
|---|---|---|---|
| `start_foreground` | *None* | `()` | Starts audio recording and promotes service to foreground. |
| `pause` | *None* | `()` | Pauses audio capture without stopping the foreground service. |
| `resume` | *None* | `()` | Resumes audio capture. |
| `stop` | *None* | `()` | Stops recording, finalizes spool file, and stops foreground service. |
| `state` | *None* | `RecorderStateResponse` | Returns current recording status, spool path, and bytes captured. |
| `post_standby_notification`| *None* | `()` | Posts an ongoing notification with a `"START"` action `PendingIntent`. |
| `get_persisted_state` | *None* | `serde_json::Value` | Reads last recorded state from disk cache. |
| `recover_state` | *None* | `serde_json::Value` | Recovers active state following process restart or OS termination. |

### The State Response Format

```rust
#[derive(Debug, Clone, Serialize, Deserialize, PartialEq)]
#[serde(rename_all = "camelCase")]
pub struct RecorderStateResponse {
    pub state: String,           // "IDLE" | "RECORDING" | "PAUSED" | "STOPPED"
    pub spool_path: String,      // Path to current audio spool file
    pub bytes_recorded: u64,     // Total bytes captured
    pub is_foreground: bool,     // Whether service holds foreground status
}
```

## 4. App-Level Integration & Feature Flags

In consumer applications (like `examples/starter`), extensions can be gated behind Cargo features:

In `src-tauri/Cargo.toml`:
```toml
[features]
default = []
recorder = ["dep:tauri-plugin-orbitkit-recorder"]

[dependencies]
tauri-plugin-orbitkit-recorder = { path = "../../../crates/tauri-plugin-orbitkit-recorder", optional = true }
```

In `src-tauri/src/lib.rs`:
```rust
let mut builder = tauri::Builder::default()
    .plugin(tauri_plugin_orbitkit::init(config));

#[cfg(feature = "recorder")]
{
    builder = builder.plugin(tauri_plugin_orbitkit_recorder::init());
}
```

And in Tauri capabilities (`capabilities/default.json`):
```json
{
  "permissions": [
    "core:default",
    "orbitkit:default",
    "orbitkit-recorder:default"
  ]
}
```

## 5. Resilience Pattern: LMK & Crash Recovery

When mobile devices experience low memory, the OS Low Memory Killer (LMK) may terminate background applications without executing graceful shutdown hooks.

The recorder extension implements disk-backed state persistence (`OrbitkitStatePersistence`):
1. **Atomic State Write**: State transitions (`RECORDING`, `PAUSED`, `STOPPED`) and spool file descriptors are written atomically to app-private cache/storage.
2. **Cold Start Recovery**: On next app launch, calling `recover_state()` checks for an orphaned spool file. If the previous process was terminated ungracefully while `RECORDING`, the extension marks the file finalized and restores clean state.
3. **No Audio Loss**: Spooled audio buffers written before process termination remain intact on disk.
