### Finding 1 (Major) — physical centre fed to a logical-coordinate monitor API; pure selector dead in production

- **Fix**: `Orbitkit::mascot_monitor()` (desktop.rs) now enumerates `app.available_monitors()`, maps each tauri `Monitor` to `MonitorInfo` (full `bounds` + `work_area`, physical px), computes the mascot window centre in physical px (`outer_position` + `outer_size`/2, i64 math, `i32::try_from` guard → primary fallback on overflow), and selects via the pure `monitor_for_point`. The `window.monitor_from_point` call is gone from the production path — the shipped selection IS the unit-tested selector. Fallbacks unchanged: `primary_monitor()`, then headless 1280×800@1.0.

- **Honest caveat**: the old production call itself (`monitor_from_point` with logical semantics on macOS/Linux) cannot execute under the headless docker gate, so "fails on old code" is proven (a) directly for the old selector semantics (mutation run above) and (b) structurally for the old production path — the `logical_mangled` assertions pin the exact `None → fallback` failure mode the old code exhibited on mixed-scale layouts.

## Round 3 (review fix on top of 0afcd12 — selection coordinate space)

Reviewer verdict on `0afcd12`: FAIL — the Major AC3/K9 issue was not yet fixed: on macOS/Linux, tao reports each monitor's "physical" `position`/`size` as logical points multiplied by **that monitor's own** scale, so per-monitor "physical" rects overlap/gap on mixed-scale layouts (e.g. Retina 1512×982pt @2x reports 3024×1964 while an @1x external sits at pt x=1512 → rects overlap 1512..3024), while window `outer_position`/`outer_size` are the window's logical geometry × the window's scale. Round 2's pure-physical comparison therefore still picked the wrong monitor on such layouts.

- **Fix**: new pure fn `selector_inputs(monitors, win_pos, win_size, win_scale, logical_space)` in `lib.rs` next to `monitor_for_point`. With `logical_space = true` it divides every monitor rect by **its own** scale and the window centre by the **window's** scale, putting selection in the one shared logical space; with `false` (Windows: tao reports true physical virtual-screen coordinates) it passes through unchanged — no division, so Windows' native-physical coords and fractional scales (1.25/1.5) stay intact. `mascot_monitor` (desktop.rs) maps `available_monitors()` to `(x, y, w, h, scale)` tuples, captures `window.scale_factor()`, and selects via `selector_inputs` + `monitor_for_point` behind `#[cfg(windows)] SELECTION_LOGICAL_SPACE = false` / `#[cfg(not(windows))] = true`. Response construction unchanged (raw work area + scale of the chosen `tauri::Monitor`).
- **Tests (F2)**, replacing the round-2 mixed-scale test: (a) macOS mixed-scale as tao reports it → mascot at pt (2400,400) selects the external (`Some(1)`); (b) window on the @2x primary, centre divided by the window's scale `(2600,600)+(200,200) @2.0 → (1350,350)` → primary; (c) Linux 2x+1x overlap layout → external; (d) Windows physical passthrough → rects/centre unchanged, secondary selected.
- **Mutation proof (live)**: disabling the division in `selector_inputs` (= old per-monitor-scaled passthrough behaviour) makes the gate exit 101 with **3 FAILED**: `test_selector_inputs_logical_space_macos_mixed_scale`, `test_selector_inputs_logical_space_linux_layout`, `test_selector_inputs_logical_space_primary_window` (centre assertion); the physical-passthrough test (d) stays green, exactly as expected (`raw/mutation-round3.log`).
